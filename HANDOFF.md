## 1. In one minute

**What it is.** Since v1.9.0, a **tools-first home-preparedness app** for any disaster, in **Thai and English**: the start screen opens on what to do when something happens (a short sourced guide for each of nine hazards), what to keep at home (the home check) and the family plan card, and since v1.10.0 two calculators for the moment itself (since v1.11.0, food by food, what in the fridge to throw out and what to keep in a power cut; what today's dust colour means at home); the 60-second game below is the optional, easier way to remember. The game is for keeping a home safe through the Thai year. Players fix up an illustrated house before a flood (ก่อนน้ำมา), spot the dangers after it (หลังน้ำลด), shut out PM2.5 dust (ฝุ่น PM2.5), find the fire risks (ไฟไหม้) or get through a night without power (ไฟดับ). Every tap teaches one action with its source, mostly a Thai agency, and every result becomes a card, a challenge link and a checklist to forward to family. The audience is Thai social-media users first, with an English version for people around the world.

## 3. How to run it

Requirements: Node 18 or later (Cloudflare uses 22). For `npm run images` and `npm run smoke`, you also need Chromium. `package-lock.json` pins `playwright-core` 1.63.0. Either run `npx playwright@1.63.0 install chromium`, or set `CHROME_PATH` to an existing Chrome or Chromium (in Claude Code cloud sessions: `/opt/pw-browsers/chromium`).

```bash
node tools/build.mjs                    # validate content + generate pages (Thai and English), SEO files and the service worker
npx wrangler@latest pages dev public    # local site + /api/e at http://localhost:8788
npm test                                # 40 rule tests (Node only, well under a second)
npm install                             # once: playwright-core for the next three
npm run smoke                           # 163 browser checks on a pinned day (18 Oct 2026); add  -- --screens docs/screens  to refresh screenshots
SMOKE_DATE=2026-12-05 npm run smoke     # the same checks on another Bangkok day (another season)
npm run images                          # re-render previews (Thai + English), checklists, sample cards, icons (set SITE_URL); -- --only a,b for some paths
npm run probe                           # tap-area overlaps + flood timings (Node only)
npm run docs                            # regenerate the safety table in docs/01 from items.json
npm run check:docs                      # check every relative link and anchor in the Markdown
```

## 6. Operating the live game

- **The rains come and go.** Before a rain wave, set `rainWarningActive` to `true` **with an end date**, `rainWarningUntil` (a Bangkok date, that day included): Prepare is recommended first until then, and the switch turns itself off the day after. Set it to `false` sooner if the water recedes (Return first). Now: on until **30 Nov 2026**. All five modes are always playable; with the switch off, the start screen recommends the mode in season (dust Dec–Mar, fire Apr, otherwise Return).
- **A topic in the news** works the same way: `featuredTopic` with `featuredTopicUntil`. Now: `"health"` until **15 Nov 2026**. Without a news topic, the recommended mode's own topic is featured (dust → 😷, fire → 🔥). Whenever you turn a switch on, give it an end date; the build warns if you don't, or if the date has passed ([#44](docs/KNOWN_ISSUES.md#44-the-featured-topic-is-switched-by-hand)).
- **What visitors see today:** `node tools/build.mjs` prints a `start` line, for example `start     2026-10-18: prepare (warning until 2026-11-30) · featured health until 2026-11-15`. Cloudflare's build log shows it too, for the day of each deploy.
- **The year turns.** The start screen follows `config.modes[].months` by itself (dust December–March, fire April). Change the months if your region differs ([#47](docs/KNOWN_ISSUES.md#47-the-season-calendar-is-editorial)); the south's November–January floods are outside this calendar, so campaigns there use `/?mode=prepare`.
- **The power cut is year-round (v1.7.0).** It has no months, so the start screen never recommends it by itself: it is always one of the small cards. Bring it forward with posts: `/ready` to read (its own preview) and `/?mode=stock` to play, after a planned power cut in the area, a storm warning or in a quiet week ([04-launch-kit](docs/04-launch-kit.md#power-cuts-and-home-stock-v170-any-time-of-year)). 5 of the 8 lessons in its carousel set are still under review and say so on the images.
- **When something is in the news (v1.9.0):** set `config.json → alert` to that hazard's guide with an end date, post the guide's picture and caption from `/posts` with its `/checklist/<id>` link, and clear the alert after. Now: `landslide` until **25 Oct 2026**. The 5-minute routine is in [04-launch-kit](docs/04-launch-kit.md#when-something-happens-the-5-minute-playbook).
- **The home check and plan card (v1.8.0)** need no switch and no season. Since v1.9.0 they are on the start screen's hub, and their pages `/kit` and `/plan` have previews of their own: link those in posts, with the names เช็กของจำเป็น and แผนครอบครัว (v1.9.1). `/?open=kit` and `/?open=plan` open the tools directly but preview as the main game ([#52](docs/KNOWN_ISSUES.md#52-a-mode-link-previews-as-the-main-game)); `/ready` and `/flood` link both and have previews of their own ([04-launch-kit](docs/04-launch-kit.md#the-home-check-and-the-plan-card-v180-any-time-of-year)). Never post a real family's plan card. Opens and shares are counted as `kit_open`, `kit_share`, `plan_open` (v1.8.1) and `plan_share` ([05-metrics](docs/05-metrics.md#the-home-check-and-the-plan-card-v180)); answers and text never leave the phone. Which result screens offer the check, and which hazard pages link both tools, is set by `config.json → hazards.<hazard>.tools` (flood and power cut today).
- **The calculators (v1.10.0)** need no switch either. Since v1.11.0 `/fridge` says what to throw out and what to keep, food by food, which makes it the post for the morning after a power cut too. `/fridge` is for the moment the power goes (and before the storm season), `/air` for the dust season from December and hazy days; both have previews of their own. Opens and shares are counted as `tool_open` and `tool_share` (mode `fridge` or `air`), with no reading, time or answer ([05-metrics](docs/05-metrics.md#calculators-v1100)). If the PCD issues a new AQI notice, the bands change in `kit.json → air` with the new source; the build stops until every edge is in it.
- **Larger text (v1.11.0):** "ก+" needs nothing from you. How many visitors turn it on is counted as `big_text` (`on` / `off`); if many do, that is the case for text sizes that follow the phone's own setting ([#81](docs/KNOWN_ISSUES.md#81-larger-text-ก-covers-the-start-screen-and-the-sheets-only-and-sizes-ignore-the-phones-text-setting), [05-metrics](docs/05-metrics.md#larger-text-and-the-real-readers-v1110)).
- **Campaign links (v1.6.0):**
  - To **play**, link `/?mode=prepare`, `return`, `dust`, `fire` or `stock` (`/en/?mode=…` in English). The game opens with that mode as the big card and its topic featured, whatever the date; nothing starts until the visitor taps. Its link preview is the main game's ([#52](docs/KNOWN_ISSUES.md#52-a-mode-link-previews-as-the-main-game)).
  - To **read**, with a preview of its own, link the hazard page: `/flood`, `/pm25`, `/fire` or `/ready` (`/en/…`). Each has that hazard's lessons, checklists and helplines, and ▶ buttons into the game. Never rename these pages; their names are in `config.json → hazards`.
  - Arrivals from `?mode=` links are counted as `view` with the label `link` ([docs/05-metrics.md](docs/05-metrics.md#campaign-links-v160)).
- **Correcting advice:**
  1. Edit the JSON with its source (Thai and English).
  2. Wait for the deploy, which takes about two minutes, and check the live site.
  3. Post **"UPDATE:"** wherever the game was shared, in each language it was shared in. Never correct advice quietly.
  4. Ship structural edits (adding, removing or disabling items, or moving slots) around midnight Bangkok time, because they reshuffle today's house ([#24](docs/KNOWN_ISSUES.md#24-some-content-edits-reshuffle-todays-house-and-old-challenge-links)).
- **If it goes viral:**
  - Static pages and images are unlimited on the free plan.
  - Only the event counter uses the Functions quota (100,000 requests a day). Lower `config.analytics.sampleRate` to `0.5` or `0.2`; the metrics SQL stays correct.
  - With **Fail open**, the game keeps working even if the quota runs out.
- **Link previews look stale:** use Facebook's Sharing Debugger → *Scrape Again*. For LINE, share a `?v=2` variant. Links shared before a preview change keep their cached preview.
- **Something broke after a deploy:** Cloudflare → Pages project → Deployments → an earlier one → *Rollback*.
- **After every push:** check the live site for something that changed (the version chip, a text), not only that CI is green ([LESSONS F6b](docs/LESSONS_LEARNED.md#f-working-in-an-ai-sandbox)).
- **Each season (April–May):**
  1. Re-check sources and hotlines.
  2. Bump `houseVersion`.
  3. Re-render the images.
  4. Re-run the tests.

  See [docs/04-launch-kit.md §5](docs/04-launch-kit.md#5-relaunch-every-rainy-season).

**Lessons in brief** (full list in [docs/LESSONS_LEARNED.md](docs/LESSONS_LEARNED.md)):

- **Measure the whole requirement.** The 44 px rule passed for items but failed for four other controls until every control was measured.
- **Headless tests aren't phones.** Real in-app browsers are still unverified.
- **Agency sites block bots.** Their wording came from PRD reposts and news, so a person must do the final check.
- **Some content edits reshuffle houses.** Adding, removing or moving items changes today's house and old challenge links, so ship those at midnight.
- **A language switch must reach everywhere the brand is drawn.** The English version first still showed the Thai wordmark on the title, cards and previews; the owner caught it from a screenshot.
- **Don't let "international" take Thai from Thai players.** Default to Thai for Thai browsers or Bangkok time.
- **A green push is not a live site.** Check the live page after deploying.
- **"On the page" is not "on the screen".** The share button passed every check for five versions while sitting below the fold on every phone; measure where the next button is.
- **Look at the screens as a visitor, not only through checks.** In v1.3.0 every check passed while the combo text ran off the screen edge and the challenge chip covered the gecko's bubble on a 320 px phone; screenshots found both.
- **Refactor before adding.** Dust and fire went onto a mode registry first, with all 244 flood houses proven unchanged; then each new mode was data.
- **Write down an action only after it succeeded,** and prefer additive git operations. History rewrites happen only on the owner's explicit request.
- **A switch someone must remember to turn off will be forgotten.** Give it an end date. And a test must not read the calendar: pin the date and take the expectation from the game's own function ([LESSONS C16, D10](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **A viral infographic is a prompt, not a source.** Keep what agencies back, flag what only a foreign agency backs, drop the rest, and re-read every sentence that describes the whole game ([LESSONS B9](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **A forced click can't see what covers the button.** The room arrow covered part of an item from v1.0 to v1.6.1 because the smoke test clicked with `force: true`; measure what lies over each tap target ([LESSONS D11](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **Run probes from the scratchpad, and read `git status` before committing.** A probe run from the repository root put a screenshot into the v1.7.0 commit, and CI can't catch a stray file once it is committed ([LESSONS E8](docs/LESSONS_LEARNED.md#e-process-documentation-and-git)).
- **Test a card with the longest text it accepts.** The first plan card silently dropped its sixth row when the entries were long; the rows now shrink together, and all six fit at maximum length ([LESSONS D12](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **A sweep finds only what it searches for.** v1.7.0 re-read the texts about the whole game for "Thai agencies", so the tagline kept saying "floods, dust and fire" until a visitor read it; when a mode or tool is added, check every place that says what the game is about ([LESSONS E9](docs/LESSONS_LEARNED.md#e-process-documentation-and-git)).
- **The product people need is the list, not the game.** Lead with what to do and what to keep, for any hazard; the game helps people remember and never gates the advice ([LESSONS A6](docs/LESSONS_LEARNED.md#a-product-and-audience)).
- **Sources disagree more than you expect.** Unplugging in lightning and leaving a tall building after a quake split the agencies once read side by side; keep what they share and record what was left out ([LESSONS B11](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **Measure where a line starts, and remember what the visitor chose.** A check measured the bottom of an item under its source links, and another forgot that the language choice carries over to the next page ([LESSONS D14, D15](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **A test stub kinder than the browser hides the bug.** Sharing sent the game's tab away from v1.0 to v1.9.0, because no test returned `null` from `window.open` the way browsers do with `'noopener'`; make stubs behave like the real API and prove each new check fails on the old code ([LESSONS D16](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **Leave Thai text alone; use markup.** A word joiner inside a Thai word moved the line break next to it; a no-wrap span fixed it, and then four "any span inside" CSS rules caught the spans ([LESSONS C18, C19](docs/LESSONS_LEARNED.md#c-engineering-and-platform)).
- **Measure the house people are playing this week.** The flood's pace looked fair in a table of timings, but the 18 Oct house, the harshest of 90, drowned a careful player's round at 15.9 s ([LESSONS D17](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **Fixing a tell can create the opposite one.** Making every wrong answer longer would have made "never pick the longest" the new trick; measure the whole distribution after a fix, and read every drafted line against its item ([LESSONS D18, B12](docs/LESSONS_LEARNED.md#d-testing-and-verification)). The icons on the answers were a second tell, so they are letters now.
- **Read what the host adds before limiting it.** Cloudflare injects scripts into every page, so the security policy leaves scripts alone ([LESSONS C21](docs/LESSONS_LEARNED.md#c-engineering-and-platform)).
- **A calculator computes only from sourced numbers, and no rounding makes it look safer.** The status comes from the exact time and the screen reads "about" (v1.10.1; v1.10.0's time off up and time left down made a time just tapped read "59 นาที"); a stepper moves by exactly its step (the + that turned 3 h 30 min into 5 h was `Math.round`), and the build checks every hour and band edge against its source ([LESSONS B13, C23](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **Right is not the same as clear.** The fridge tool passed 157 checks and a cross-check, and its owner couldn't read it. Read every tool as a first-time older visitor: one question at a time, nothing started before it is asked, a word first and one line after, the source once ([LESSONS A8](docs/LESSONS_LEARNED.md#a-product-and-audience)).
- **Ask the unit; and when two agencies differ, choose a main text and name the other on its line.** AQI 152 is orange and 152 µg/m³ red; the PCD and the DOH advise differently at three levels ([LESSONS A7, B14](docs/LESSONS_LEARNED.md#a-product-and-audience)).
- **Cross-check a calculator with a script written from the source, not with its own function,** and wait for an animation to end before judging a screenshot ([LESSONS D21, D22](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **A calculator never tells anyone to throw away medicine.** The fridge tool turned Ready.gov's general "discard after a day, unless the label says otherwise" into "throw it out" for every cold medicine, insulin included, which the FDA keeps good for 28 days at 15–30 °C; both audits of v1.11.0 caught it. Find the source for the commonest case and show the condition first ([LESSONS B16](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **A chart row can be right in its country and wrong in ours.** "Fish sauces: discard" would have told Thai families to throw out their น้ำปลา; leave out a row that doesn't fit, flag the doubtful ones, and say "not on the list: if in doubt, throw it out" ([LESSONS B15](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **The person who forwards is not the person who reads.** Older receivers get a picture, not a link; show their own advice without ticks, name every number, write a share text that is true without the picture ([LESSONS A9](docs/LESSONS_LEARNED.md#a-product-and-audience)).
- **Check a class name before using it, cross-check every item at every edge, and let a test wait for the app's own history steps and smooth scrolls** ([LESSONS C24, D23, D24, D25](docs/LESSONS_LEARNED.md#d-testing-and-verification)).
- **Copy written from a source takes on the source's English.** The power-cut lessons, written from American pages, said "flashlight" next to the flood lessons' "torch"; the English is British now, and the sources keep their own words in their notes ([LESSONS B10](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).
- **Read what the owner's other project already learned, then test it live.** FloodWatch had already tried the Thai feeds, refuted some and written down each one's time rule; a feed's own labels can still be wrong (GISTDA's "Z" is Bangkok time, WAQI's demo answered Bangkok with Shanghai) ([LESSONS B18, B19](docs/LESSONS_LEARNED.md#b-safety-content-and-research)).

## 10. Access, accounts and secrets

- **The repository contains no secrets,** and the game needs none to run.
- **You will need:**
  - a **Cloudflare account** for the Pages project
  - optionally, a **custom domain**
  - a Cloudflare **API token** in `.env` (git-ignored; `.env.example` lists the format). It needs *Account → Cloudflare Pages → Edit* and *Zone → DNS → Edit* on `autobahn.bot`, and, for the metrics SQL and Web Analytics, *Account Analytics → Read* and *Web Analytics → Edit*. Never commit it.
- **Third-party material:**
