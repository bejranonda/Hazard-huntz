## 1. In one minute

**What it is.** A 60-second mobile web game, in **Thai and English**, for keeping a home safe through the Thai year. Players fix up an illustrated house before a flood (ก่อนน้ำมา), spot the dangers after it (หลังน้ำลด), shut out PM2.5 dust (ฝุ่น PM2.5) or find the fire risks (ไฟไหม้). Every tap teaches one action from a Thai agency, and every result becomes a card, a challenge link and a checklist to forward to family. The audience is Thai social-media users first, with an English version for people around the world.

**What's done:**

- **Game:** four modes over three rooms (หน้าบ้าน, ห้องนั่งเล่น, ครัว): ก่อนน้ำมา and หลังน้ำลด (flood), ฝุ่น PM2.5 and ไฟไหม้ (v1.5.0). A daily house per mode, streaks, challenge links, offline play. The start screen recommends the mode in season.
- **Content:** 68 safety items (57 verified, 11 flagged ⚠️ partial; 66 in playable rooms) in 8 topics, and 25 decoys, from 67 dated sources, in Thai and English. Dust and fire (v1.5.0) rest on the Department of Health, DDPM and MEA, cross-checked with WHO and the US Fire Administration ([KNOWLEDGE §22](docs/KNOWLEDGE.md#22-a-game-for-the-whole-year-v150)).
- **International version (v1.2):** `/en/` game, `/en/learn` lessons, `/en/c/…` and `/en/checklist/…` links; English link previews (49 images); `hreflang` between each Thai page and its English twin; first-visit language guess that keeps Thai players on Thai; English wordmark "Baan Rod Mai?" ([KNOWLEDGE §18](docs/KNOWLEDGE.md#18-international-version-and-social-previews)).
- **Sharing:** result cards that print the challenge link for their own house, checklists, challenge links with a real **challenge back** (both scores, the card attached), link previews, per language.
- **Fun and coming back (v1.3.0):** the safety book (สมุดบ้านรอด, 41 lessons to collect, grouped in 6 topics, kept on the device), end-of-round moments by score with a perfect-10 stamp, a feel-only combo, new sounds, streak milestones, and replay buttons above the lessons ([KNOWLEDGE §20](docs/KNOWLEDGE.md#20-fun-and-sharing-features-v130)).
- **Search and AI search:** `/learn`, `/en/learn`, `/llms.txt`, `/sitemap.xml` (with language pairs), `/robots.txt`, canonical links and JSON-LD, generated by the build. GitHub About, homepage and 20 topics are set.
- **Forecast link:** the water-level button opens **BKK FloodWatch** (`https://flood.autobahn.bot/`), the owner's own Autobahn Bot project.
- **Platform:** live Cloudflare Pages deploy (pushes to `main` deploy by themselves), anonymous metrics, and GitHub Actions CI (build, rule tests, docs link check, browser checks).
- **Review and optimisation:** live-site UI/UX evaluation and 3-loop refinement (9.74/10), tap overlaps at 0%, senior-friendly timer copy. Full audit in [review/](review/README.md).
- **Docs:** the six deliverables plus the maintainer reference and the guidance for AI assistants.

**Checks.** The build passes, with its content validation and size budget (start screen **183 KB** compressed against a 500 KB limit). All **20 rule tests**, **58 browser checks**, the **0% tap-overlap probe** and the docs link check (all relative links) pass locally and in CI.

**What's not done:**

- real-phone testing in LINE, Facebook and TikTok
- Web Analytics switched on, and the sitemap submitted to the search consoles
- a human review of the ⚠️ items
- the native-speaker language check (English and Thai) that the owner will supply
- three more rooms
- version 2's combined run

Details are in sections 2 and 8.

## 3. How to run it

Requirements: Node 18 or later (Cloudflare uses 22). For `npm run images` and `npm run smoke`, you also need Chromium. `package-lock.json` pins `playwright-core` 1.63.0. Either run `npx playwright@1.63.0 install chromium`, or set `CHROME_PATH` to an existing Chrome or Chromium (in Claude Code cloud sessions: `/opt/pw-browsers/chromium`).

```bash
node tools/build.mjs                    # validate content + generate pages (Thai and English), SEO files and the service worker
npx wrangler@latest pages dev public    # local site + /api/e at http://localhost:8788
npm test                                # 20 rule tests (Node only, well under a second)
npm install                             # once: playwright-core for the next three
npm run smoke                           # 58 browser checks; add  -- --screens docs/screens  to refresh screenshots
npm run images                          # re-render previews (Thai + English), checklists, sample cards, icons (set SITE_URL)
npm run probe                           # tap-area overlaps + flood timings (Node only)
npm run docs                            # regenerate the safety table in docs/01 from items.json
npm run check:docs                      # check every relative link and anchor in the Markdown
```

## 6. Operating the live game

- **The rains come and go.** Set `rainWarningActive` to `true` before a rain wave (Prepare is recommended first) and to `false` as the water recedes (Return first). All four modes are always playable; with the flag off, the start screen recommends the mode in season (dust Dec–Mar, fire Apr, otherwise Return).
- **The year turns.** The start screen follows `config.modes[].months` by itself (dust December–March, fire April). Change the months if your region differs ([#47](docs/KNOWN_ISSUES.md#47-the-season-calendar-is-editorial)). For a dust or fire campaign, set `featuredTopic` to `"air"` or `"fire"`, or leave it `null` and the season's topic is featured.
- **Correcting advice:**
  1. Edit the JSON with its source (Thai and English).
  2. Wait for the deploy, which takes about two minutes, and check the live site.
  3. Post **"UPDATE:"** wherever the game was shared, in each language it was shared in. Never correct advice quietly.
  4. Ship structural edits (adding, removing or disabling items, or moving slots) around midnight Bangkok time, because they reshuffle today's house ([#24](docs/KNOWN_ISSUES.md#24-some-content-edits-reshuffle-todays-house-and-old-challenge-links)).
- **If it goes viral:**
  - Static pages and images are unlimited on the free plan.
  - Only the event counter uses the Functions quota (100,000 requests a day). Lower `config.analytics.sampleRate` to `0.5` or `0.2`; the metrics SQL stays correct.
  - With **Fail open**, the game keeps working even if the quota runs out.
- **Link previews look stale:** use Facebook's Sharing Debugger → *Scrape Again*. For LINE, share a `?v=2` variant. Links shared before a preview change keep their cached preview.
- **Something broke after a deploy:** Cloudflare → Pages project → Deployments → an earlier one → *Rollback*.
- **After every push:** check the live site for something that changed (the version chip, a text), not only that CI is green ([LESSONS F6b](docs/LESSONS_LEARNED.md#f-working-in-an-ai-sandbox)).
- **Each season (April–May):**
  1. Re-check sources and hotlines.
  2. Bump `houseVersion`.
  3. Re-render the images.
  4. Re-run the tests.

  See [docs/04-launch-kit.md §5](docs/04-launch-kit.md#5-relaunch-every-rainy-season).

## 10. Access, accounts and secrets

- **The repository contains no secrets,** and the game needs none to run.
- **You will need:**
  - a **Cloudflare account** for the Pages project
  - optionally, a **custom domain**
  - a Cloudflare **API token** in `.env` (git-ignored; `.env.example` lists the format). It needs *Account → Cloudflare Pages → Edit* and *Zone → DNS → Edit* on `autobahn.bot`, and, for the metrics SQL and Web Analytics, *Account Analytics → Read* and *Web Analytics → Edit*. Never commit it.
- **Third-party material:**
  - the Kanit font subsets, under the SIL OFL (`public/fonts/OFL-Kanit.txt`)
  - agency guidance, summarised and linked, never copied as images
